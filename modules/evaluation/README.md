# Modules — evaluation（评价实现，预留）

写作质量的评价实现：把「好/不好」拆成可观察、可验证的维度。

## 状态：预留

迁入的[学术评价设计](../../ideas/evaluation_design.md)由学术方向接续，仍是研究 proposal。
本目录尚无自动 evaluator 或实验结果；迁移不改变通用评价模块的预留状态。

「摆脱 AI 味」「写得更好」这类目标必须拆成可观察问题才能比较修改前后是否更好：

- 套话（空泛表达）
- 空泛判断（无证据支撑的断言）
- 重复总结
- 机械段落结构
- 不必要的修饰
- 缺少具体信息
- 作者声音不一致

## 设计立场

- 先判断哪些维度**跨场景成立**、哪些只是**某种文体的偏好**。
- 学术领域专属标准（贡献声明强度、证据覆盖、因果限定）不并入通用评价；
  领域专属标准保留在各自模块内（见 `memory-docs/detail_mem/DECISIONS.md`）。
