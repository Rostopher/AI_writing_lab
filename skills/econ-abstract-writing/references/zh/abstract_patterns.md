# WHFFF：内容分工与结构选择

[English](../abstract_patterns.md) | 简体中文

在五个问题的答案已经形成、需要决定摘要顺序或压缩篇幅时使用。

## 默认安排

| 位置 | 要完成的事 | 内容选择 |
|---|---|---|
| W | 交代核心问题 | 具体对象与关系，尽早让读者知道要回答什么。 |
| H | 交代关键方法 | 实证研究突出回答问题的设计；理论研究交代关键模型、设定或分析方法。 |
| F1 | 给出直接答案 | 最重要的方向、量级或命题，保留理解结论所需的条件。 |
| F2 | 进一步解释主结果 | 优先机制证据；也可用重要的异质性、对照或另一项发现。 |
| F3 | 补全发现 | 重要的代价、长期结果、经济后果或其他改变理解的结果。 |

先选值得写的发现，再判断需要多少背景和方法。多个结果的重要性不等时，按它们对研究问题的解释力排序，
不用“跑回归的先后顺序”或“哪张表先出现”决定摘要顺序。

## 何时调整结构

| 情况 | 可采用的安排 | 判断依据 |
|---|---|---|
| 问题和设计一句能说清，字数紧 | W+H → F1 → F2 → F3 | 合写后，读者仍能理解研究对象、问题和证据来源。 |
| 研究设计本身需要解释 | W+H → H → F1 → F2 → F3 | 两句方法各有任务，例如先交代关键比较，再解释数据及其实现。 |
| 读者需要一个具体背景才能理解问题 | 简短背景 → W/H → F1 → F2 → F3 | 背景提供理解问题必需的信息，并快速进入这篇论文。 |
| 论文只有一两条独立发现 | W → H → F1 → F2，或进一步合写 | 不把同一结果拆成几句重复话，不为句数补新结果。 |
| 理论论文的方法已包含在问题或命题设定中 | W/模型设定 → 核心命题 → 条件或机制 → 推论 | 不强行加入“数据与识别策略”，关键条件不能因压缩而丢失。 |
| 有具体且受结果支持的研究含义 | 让最后一个发现自然连接该含义 | 含义必须明确到研究能支持的程度；不额外添加泛泛的意义句。 |

F2 回答的“为什么会出现这个结果”是机制问题；研究整体“为什么重要”是另一个问题。
将二者区分开，可以避免把一句空泛的贡献宣称当成机制发现。

## 怎样选择第二、第三个发现

逐项问：这条结果是否来自论文？它是否增加信息？如果删掉，读者会漏掉什么？

- **机制：** 论文检验了哪条路径？证据足以确认机制，还是仅与机制相符？按原证据表达。
- **异质性：** 效果集中在哪里？这种差异是否帮助回答论文的核心问题？
- **对照与代价：** 主结果是否伴随另一个方向不同但重要的后果？
- **长期结果：** 主效应维持、衰减还是逆转？保留实际观察的时间范围。
- **经济后果：** 福利、成本收益、效率或分配结果是否确实被估计或推导？

选择最重要的一项或少数几项，不把这些类别当作全部需要填满的栏目。
一个结果同时承担多种功能时，可以在同一句说明。

## 压缩字数时

优先删去空泛背景、重复结论、可留给正文的方法细节和笼统意义句；再考虑合写 W/H、
删除次要发现。保留主结果的量级与单位、关键比较、研究范围及改变结论含义的条件。
用更清楚的动词减少绕行，不靠长串从句把多句挤成一句。

字数目标来自作者或核实后的投稿要求；研究语料中的词数和句数分布只帮助估计篇幅。
