# 经济学顶刊摘要结构研究：探索与实施设计

> 版本：0.2；日期：2026-09-08；状态：待执行的研究设计。
> 本文是后续 agent 的执行入口。本轮仅交付设计与 prompt，未抽取实际研究样本、运行统计或调用标注模型。
> 首轮研究单位是 **Abstract**，不含 Introduction。后者应另立设计，不能复用本研究的词数或句数阈值。
> v0.2：年份窗口由 2015–2024 扩为 2015–2026（用户决定），2026 标为 partial year；已核验上游五刊覆盖与 AER 2018 年 4–5 月合刊情况，见第 3 节。

## 1. 问题与可支持的结论

研究 econ-write 的摘要建议在已有经济学 Top Five 论文中有多普遍，在哪些期刊、年份和研究类型下适用，以及四功能框架遗漏了什么。研究对象是已发表摘要的组织特征；不能从这些特征推断发表原因或写作建议的因果效果。

| 编号 | 待检验 claim / 假设 | 需要的证据 |
|---|---|---|
| H1 | 摘要通常落在 100–150 个英文词，且不超过 150 词 | 明确计词口径下的分布、期刊及年份分层 |
| H2 | 摘要包含做什么、怎么做、发现什么三个功能，部分另有意义说明 | 有证据片段的功能标注、缺失与不确定比例 |
| H3 | What 占 1–2 句、How 占 1 句、Findings 占 1–2 句，功能依次出现 | 多标签句子位置、占用句数、重叠及顺序指标 |
| H4 | 四功能框架足以描述大部分摘要内容 | 框架外内容的原文、开放描述、归纳类型及覆盖量 |
| H5 | 其他摘要规则具有较高符合度，但可能依研究类型变化 | 分规则的适用性、文本证据、例外与人工核验 |
| H6 | 候选低成本模型足以承担可审核的批量标注 | 同样本双模型比较、人工参照、失败率和实际成本 |

“通常”“大部分”“较高”目前是待量化问题，不预设 80% 或 95% 等结论阈值。先报告比例与不确定性，再讨论它们能否成为有边界的建议。不能将“未支持普遍适用”改写成“建议没有价值”。

成果形态：先形成方法与语料描述报告；通过可靠性检查后，形成摘要写作经验笔记。若发展成论文，本设计对应研究问题、数据、测量和局限部分。最小验证为开发集加独立 pilot，失败条件见第 11 节。

## 2. 依据、规则版本与限制

- 来源：[econ-write 主文件](../repos/econ-writing-skill/skills/econ-write/SKILL.md)，固定 commit `f2bf7a22c5e3b37921a5e6c73bd1fb380a5e00e8`，`WRITING THE ABSTRACT` 部分。它是被研究的建议，不是必须让文章符合的标准。
- 上游理解：[精读笔记](../notes/pipelines/econ_writing_skill_review.md)。外部仓库只读，不修改或安装它来开展本实验。
- AER 当前投稿指南要求摘要不超过 100 词，已于 2026-09-08 核验。因此 skill 的 100–150 词不能当成五刊的共同规范。[AER Submission Guidelines](https://www.aeaweb.org/journals/aer/submissions)
- 另外四刊的现行与历史限制尚未逐一核验；不得补写未经核实的数字。投稿稿件要求也不自动等同于最终发表摘要的历史约束。
- 上游 schema 有 `abstract` 字段并允许为空；**尚未核实五刊实际覆盖、文本质量或年份完整性**。

“是否最后写摘要”“是否从引言提炼”等过程建议记为 `not_observable_from_abstract`。单凭发表摘要不能检验，不能判定通过。

## 4. 数据入口与样本台账

遵循数据路由：采集维护在 `playwright_crawler`，论文工作区由 `paper-workspace` 物化至 `papers/`，本实验从物化结果建立派生表，不手改生成物、不重复爬取。

先只读检查少量上游元数据、现有 workspace manifest、实际可用命令及 schema。当前 `paper-workspace` skill 描述的是远程库 ID 到本地工作区的流程，不能假定已支持爬虫文件批量导入。若缺 ID 映射、abstract 字段或适配，提出最小接入方案并说明证据；不要手写受管理的 `papers/metadata.json` 绕过流程。纯覆盖诊断可只读上游元数据，不把它冒充已接入的研究数据集。

| 字段组 | 每条候选记录最低内容 |
|---|---|
| 身份 | `article_id`、原始 DOI、规范化 DOI、原始期刊名及标准代码、标题 |
| 时间与类型 | 卷期发表年份、online-first 日期（若有）、原始文章类型、纳入状态及原因 |
| 来源 | workspace canonical ID / revision、原始记录定位、来源版本或文件 hash、提取时间 |
| 原文 | `abstract_raw`、原文 hash；原文不覆盖 |
| 派生文本 | `abstract_normalized`、清洗版本、规范文本 hash、清洗记录 |
| 可用性 | `available` / `missing` / `suspected_truncated` / `extraction_error` / `non_english` / `needs_review` |

DOI 匹配时去 URL 前缀及首尾空白、统一大小写，保留原值。无 DOI 用来源稳定 ID；候选重复用标题、年份和来源辅助核验，不以模糊标题自动合并。同 DOI 摘要不同应记录版本冲突，按核实的发表版本选取并保留其他版本。online-first 与卷期记录不能重复计数。

流失表：候选记录 → 去重后文章 → 类型/语言合格 → 摘要可用 → 开发/pilot 入选 → 各模型成功 → 人工核验。区分缺少摘要与摘要未写某功能。长摘要不能因超过 150 词被剔除或截断。

缺失率只能相对于已知元数据框架计算；框架不完整时称“已采集记录中的覆盖率”。检查各刊各年卷期及来源覆盖，不能把没抓到文章当作文章没有摘要。

## 5. 确定性文本处理

### 5.1 清洗和计词

只处理可追踪的格式内容：HTML 标签及实体、Unicode NFC、布局换行和空白；仅在确认是站点包装时移除摘要标题、版权、关键词或 JEL 栏目。疑似正文和附加说明保留并标记，禁止按语义删除“不像摘要”的内容。PDF 行末连字符不能普遍直接拼接，需来源可验证。

主口径 `word_count_v1`：英文单词与数字表达式计数，词内撇号和连字符保留为一个 token（`don't`、`difference-in-differences`），`3.5`、`1,000` 各计一个；独立标点、数学符号、百分号不独立计词。选择支持 Unicode 的明确实现，记录正则或库版本，提供 token 列表供抽查。公式和非拉丁符号另记疑难标记。

辅助口径 `whitespace_count` 按规范文本空白切分，仅作敏感性检查。不声称任一口径等同出版社计词方式。优先人工检查两种计词跨越 100/150 边界的文章。

派生 `word_count`、`sentence_count`、`word_count <= 150`、`100 <= word_count <= 150`。互斥分箱为 `<100`、`=100`、`101–150`、`>150`；另报 `<=100`，避免混淆 AER 边界。

### 5.2 切句

使用固定英文切句工具并记录版本规则。Python 先切句并编号 `1..N`，模型不重新切句。保存每句在规范文本中的 `[start, end)` Python 字符偏移（不是字节或 UTF-16 单元）和精确原文。

开发集检查缩写（`U.S.`、`e.g.`）、小数、人名首字母、括号、分号、引号、公式。保留人工修正的边界、原因及原始边界。切句规则变化必须增加版本并重算受影响样本，旧标注不能直接套到新 ID。

确定性验证覆盖计词边界、清洗、切句偏移回切、去重版本冲突、失败样本保留。使用可控合成例子保护契约；真实摘要用于抽查，不把少数样例表现当作完整正确性。

## 6. 功能标注与类型边界

核心 prompt：[结构标注 prompt](abstract_structure_annotation_prompt.md)。模型指令为英文，研究报告为中文。

采用“句子为对齐单位，原文片段为证据”的多标签标注。一句可包含多个功能，同一功能可跨句；不要求四类必然出现。

| 标签 | 操作定义 | 需要避免的混淆 |
|---|---|---|
| `what` | 明确研究问题、研究对象或开展的研究任务 | 宏观背景重要性不自动是研究问题 |
| `how` | 数据、设计、模型、方法或用于解释结果的机制 | “我们研究”不算方法；不从结果猜识别策略 |
| `findings` | 本文得到的具体结果、命题、事实或方法性质 | 目标不是结果；理论结果无需数值效应 |
| `why_it_matters` | 本文研究/结果引出的解释、政策、理论或应用意义 | 一般议题重要性通常是背景；明确数据/工具用途也可表达意义 |

**What 的原文歧义需要保留。** 上游允许 research question 或 main insight。主标注用上述窄定义，同时为 findings 片段标 `central` / `secondary` / `unclear` 的 `finding_focus`。Python 构造宽口径 What = 窄 What ∪ 明确 central finding 所在句。两种口径均报告覆盖、句数、顺序；宽口径是可审查的操作化，不宣称完全还原作者意图。不能仅凭窄口径缺失反驳原规则。

How 每个证据另标 `how_aspects`：`data/design/model/mechanism/other_method`，可多选。How 出现不等于所有细项齐全；另统计实证的 data + design、理论的 model + mechanism 是否同时明确出现，以及是否在同一句。混合论文分支分别报；不因“实验”一词就补出样本/数据来源。design 是否提供具体识别关键词留给规则审查，两个测量不混同。

研究类型按摘要证据标 `empirical` / `theory` / `mixed_or_structural` / `methods` / `unclear`；另标 empirical、theory、structural 三个非互斥 component，各取 `yes/no/unclear`。`no` 仅指摘要未出现明确证据，不表示全文没有。不能因出现“model”就判为经济理论或结构模型。

类型用于分层及方法规则适用性，不决定是否纳入：描述性实证可没有因果关键词，统计模型不必是经济理论，方法论文可以同时包含证明与应用。

每句还保留：

- `other_content`：功能明确但不属于四类的实质片段，附短的开放功能描述。
- `uncertain_content`：不能可靠判定的实质片段，附候选功能和简短原因。
- `connective_only`：整句只有衔接或形式内容、没有独立实质命题时才为 true。

同句背景从句和结果从句可分别进入 other 和 findings。已知背景不是“不确定”，难以判断不是“其他”。无需给每个连接词贴标签，但不能忽略未归类的实质从句。

框架外功能先开放标注，再从开发集归纳候选词表（背景、动机、文献缺口、适用范围、局限、数据贡献等仅是可能方向）。词表冻结后用于 pilot，保留 `new_other`；保存原始描述及人工归并，不能为提高框架覆盖率硬塞回四类。

## 7. 其他规则的检查

独立使用[规则审查 prompt](abstract_rules_audit_prompt.md)，作为第二阶段先验证小样本，避免“找违规”影响结构标注。没运行时记“未检查”，不以结构结果代替。

| 规则 | 测量 | 边界 |
|---|---|---|
| 具体表达发现 | 结果及具体性证据 | 数字不等于具体结果；理论命题和方法性质也可具体 |
| 不提其他文献 | 正则候选 + 模型语义及 brief puzzle 例外 | 没有作者年份也可能提文献；方法人名不一定是文献讨论 |
| 不用被动语态 | 精确语段与语法判断 | 区分语法被动和形容词；不直接推断质量 |
| 不用不必要术语 | 术语、上下文解释、可替代性 | 受众相关；模型判断不等于读者理解实验证据 |
| 不超过 150 词 | Python | 与 100–150 区间分别报告 |
| 实证写识别关键词 | 命名 / 描述设计但未命名 / 未出现 / 不确定 | 描述性实证保留在字面检查内，另报因果设计适用性 |
| 理论写机制 | 命名 / 描述 / 未出现 / 不确定 | 不从模型名补写机制 |
| 结构论文写反事实结果 | 明确结果 / 仅计划 / 未出现 / 不确定 | 普通观察比较不自动是反事实 |
| 最后写、从引言提炼 | 摘要不可观察 | 不纳入符合率分母 |

先保留状态、适用性和证据，再由代码映射规则，不让模型输出“整体合格”。optional implication 缺失、框架外内容、不适用与字面偏离分开。混合论文可进入多项分母。

“所有实证要关键词”的字面统计和“有因果识别需求的实证”条件统计都保留，不能通过缩小适用分母美化符合率。术语必要性读者研究不是首轮必做，其结论先标证据不足。

## 8. Prompt 与模型执行协议

仅发送对应 `SYSTEM_PROMPT` 和程序构造的 `USER_PAYLOAD`，不发送整个设计、假设、期刊、作者、年份、声誉或另一个模型答案。匿名 `article_id` 和固定句子列表即可；默认不发送标题，避免补入摘要未写的信息。

执行者依据供应商官方文档核验真实 model ID、价格和参数。记录 `provider`、`base_url`、`requested_model_id`、`returned_model_id`、版本（若可得）、推理模式、温度、输出上限、响应格式、价格核验日期及币种。不能虚构 flash/pro API 名或默认哪个一定更强。temperature=0 仅在支持时使用，不代表完全确定性。

调用前配置 `max_requests`、`max_total_tokens`、`max_cost`，先 dry-run 和估算。已有预算/授权内直接执行；真实模型 ID、凭据或费用上限缺失时，完成独立准备后取得缺失信息。本设计阶段不预先调用付费模型。

每篇同输入、同 prompt 版本，两个模型各调用一次。比较相同任务契约与输出要求；参数或推理开销不同如实记录。先比较有效输出比例，再分析共同成功子集上的标签差异。

校验 JSON、字段枚举、文章 ID、句子全覆盖且不重复、引文精确子串、角色与 finding_focus 一致性、空类别及占位文本。按字符串查找恢复语段偏移；同句重复片段导致位置不唯一时转人工，不任选一次。

保留失败请求、原响应及错误。暂时性网络/限流最多额外重试 2 次，计入预算；认证错误不重复请求。格式/契约失败最多 1 次显式修复请求，仅提供原输入、原响应及校验错误，不加标签暗示。区分原始与修复成功率；失败不以另一个模型答案补齐。

缓存键包含规范文本 hash、切句边界/版本、完整 system/user prompt hash、模型与参数。原始输出不覆盖，指标可重算。无固定底层模型版本时保留调用时间和返回标识，说明复现限制。

## 9. 分阶段执行与人工参照

### A. 数据与契约探查

完成覆盖表、来源映射、小规模计词/切句检查、输入输出样例及 API dry-run。未有真实结果时可用明确标注的合成 fixture，不能混入研究样本。

### B. 10–20 篇开发集

人工先按 codebook 标注，再看模型结果。若只有执行 agent、没有人类复核，标明“agent 初步核验”，不能命名 human gold。修改标签边界、prompt、切句及框架外分类并保留理由。开发集可有意挑难例，不用于最终普遍性估计。

### C. 冻结后 100 篇 pilot

冻结样本、prompt、计词切句和配置，再双模型运行。预先每刊随机选 5 篇共 25 篇供人工审核，独立于模型是否分歧；另审分歧、抽取异常、格式失败和难例。额外集合记录选择来源，与随机集合去重、分别统计。

建议随机 25 篇由两名人工独立标注后仲裁；单人条件下保留为单人参照，不声称测得人际一致性。人工首次只看相同摘要和固定句子，不看模型及期刊身份。全文核验类型另存字段，不覆盖 abstract-only 答案。

核验指标：

- 句子×功能二元标签的逐类 precision/recall/F1、macro F1、完整标签集合一致率；无正例记 NA 并报分母。
- 模型间逐类一致率及分歧；不能视为准确率。
- 人工参照下类型混淆及边界误判，尤其 What/Findings、背景/意义、How/Findings。
- 引文定位有效率与实质支持性人工核验；精确匹配不等于语义正确。
- 框架外内容漏标、过度拆分或硬塞进核心标签。
- 各模型原始失败率、修复率、重试、费用与耗时；共同成功子集之外的流失构成。

需要区间时按文章重抽样，不能将篇内句子当独立文章。小人工样本、低频标签和有意难例不能提供精确总体准确率，同时报告原始计数。

### D. 扩展决定

来源/切句/校验/流失没有未解释错误、关键标签无持续系统误读、有人工审核证据，才建议批量语义分析。若存在关键误差，改 prompt 后另取验证样本、选择其他模型、扩大人工审核或暂缓语义结论。

不设未经论证的单个 F1 门槛；先说明用途允许的错误及复核成本。pilot 后改 prompt，不能继续把同一 pilot 当独立验证集：保留旧结果，另抽验证集或明确为探索性复算。

全量年份、缺失处理、模型与预算由用户依据 pilot 决定。可靠性不足也可完成探索交付：解释为什么暂不支持批量研究，不强行交出符合率。

## 10. 派生指标与统计口径

模型判断类型、功能和语段；计数、列表、顺序及比例均由 Python 推导。

1. **长度**：按刊/年报 N、缺失、均值、中位数、分位数和词数箱。类型分层标明标签来源和不确定性。
2. **功能列表**：如 `what: [1]`、`how: [1,2]`，去重排序；明确缺失是 `[]`，模型失败为缺失值，不能也记 `[]`。
3. **出现状态**：明确证据为 present；无明确证据但有对应候选不确定片段为 unclear；两者都无才 absent。present 仍可伴其他边界歧义，另保留 ambiguity 标记。
4. **覆盖**：前三类均明确 present、Why 出现、四类均出现分别报告。unclear 单列；下界只计确定满足，上界可计全部 unresolved 为满足，说明是识别边界而非统计置信区间。
5. **句数**：各功能触及的不同句子数。What 1–2 / How 1 / Findings 1–2 同时给总体分母与该功能 present 条件分母。Why 无固定句数要求。另报只有单个核心功能且无 other/uncertain 的句子数。多标签合计可超过总句数。
6. **文本占比**：语段偏移与计词 token 求交，同功能 token 去重；功能间允许重叠，另报核心功能 token 并集。语段应覆盖完整实质从句；边界不可靠时停用占比结论，保留句子指标。
7. **顺序**：记录首现句号，仅在相关功能明确 present 的子样本比较。`<` 为严格先后、`=` 为共现，不把 tie 当严格顺序。另测块顺序 `max(前功能句号) < min(后功能句号)`，首现递增不保证后续不交织。分别检查前三功能及四功能子集；Why 缺失不算违规。
8. **What 敏感性**：覆盖/句数/顺序均算 narrow 和 inclusive。如果定义改变就改变结论，测量歧义写入主结果。
9. **框架外内容**：有 other 的文章/句子比例、经审核的语段占比、类别频次与原文案例。uncertain 和格式残余不计作确定的新功能。
10. **规则矩阵**：逐项报适用、不适用、不确定、例外、偏离候选及人工核实数量。不输出整体合格分，不把 optional、不可观察或未运行记为失败。

等额 pilot 整体比例只描述 pilot 或等权期刊平均，不是全部 Top Five 文章的篇数加权比例。总体估计需要有效框架、抽样概率及权重；缺失引入的偏差不会被统计区间消除。全量已有语料描述不需要伪造抽样误差，外推限于实际覆盖。

宽口径 What 的 centrality 若为 unclear，则相应宽口径覆盖也可能 unresolved；不能按 absent 处理。句数和顺序遇到可能改变结论的 uncertain 片段时，记录“基于已确认标签的观察值”并另列 unresolved，不能直接宣布通过或违规。

“摘要没写方法”不等于“论文没有方法”；类型不是已读全文后的结论。对可疑截断/损坏文本的标签保留为诊断，不直接计入明确功能缺失；人工确认完整后才恢复进入语义统计。
