# econ-writing-skill 精读：从经济学写作指南到任务模式

> 日期：2026-09-08。对象为本地固定快照 `f2bf7a22c5e3b37921a5e6c73bd1fb380a5e00e8`（包版本 0.1.2）。
> 证据范围：主 skill、专项材料、来源目录、示例、评价用例及安装测试的静态核查；抽查 Cochrane、Head、Bellemare、Evans 原始来源，并核验一项 AEA 期刊事实。
> 本轮没有安装或修改参考 skill，没有执行写作对照实验，也没有运行安装测试。不能据此确认实际输出优于其他 skills。

## 1. 核心认识

这个项目把经济学写作经验整理成一套可由模型执行的编辑说明：先明确读者和中心贡献，再决定章节功能，最后处理表达、专项写作与审阅。它的主要价值是将抽象建议落到具体动作和检查项。

“正规”的可核验部分包括署名来源、明确的任务模式、按需读取的专项文件、示例与评价用例、规范的安装与镜像管理。但来源声望、规则可追溯、工程完整和输出效果是不同维度：有出处的建议也可能在改编中变得过强，完整的安装测试也不能证明写作结果可靠。

当前适合作为经济学写作的候选编辑助手，尤其是已经有研究材料和草稿时；不宜将其评分直接解释为投稿就绪程度，也不能把规则目录当作完整文献检索与证据核验系统。

## 2. 作者怎样组织这套方法

主入口是 [skills/econ-write/SKILL.md](../../repos/econ-writing-skill/skills/econ-write/SKILL.md)。
本快照主文件为 739 行，另有四份专项材料；它们通过 Markdown 指针由模型按任务读取，没有另一个负责写作的应用程序或固定执行引擎。

```text
用户任务 + 原文/研究材料
  → 判断论文类型、写作环节和任务模式
  → 应用读者、中心贡献、信息顺序等核心原则
  → 使用相应章节结构，按需读方法/审阅/LaTeX/专项文件
  → 生成草稿、修改稿或诊断报告
  → 按检查清单复查；事实核验仍需证据与实际执行
```

这里的箭头是对提示词组织方式的解释，不表示已实现程序化阶段控制。研究材料、引用核验结果和问题清单没有被规定成统一机器可校验的数据格式；流程能否执行完整，仍受模型、上下文和使用要求影响。

## 3. 真正值得学习的写作经验

### 3.1 让读者尽快知道问题、发现和贡献

主文件首先要求明确中心贡献，并将主要信息放到前面。这影响整篇文章的组织，而不只是句子长度：结果段落应解释发现，而非重演研究者依次跑过哪些回归；引言应让读者知道论文回答了什么问题，以及答案为什么值得关注。

Cochrane 原文确实支持中心贡献、具体结果、读者优先和信息前置。这些是经验性写作指导，并非对所有文体效果的实验认证。[原始指南，印刷页 1–3](https://www.fma.org/assets/docs/membercontent/writing_cochrane.pdf)

对我们有用的操作：在起草前写一张简短材料卡，列出问题、主要发现、证据位置和适用范围；写作时用它检查段落是否推进核心论证。材料卡是本项目使用建议，不是上游已有强制格式。

### 3.2 把章节拆成要完成的功能

摘要回答做什么、怎么做、发现什么、意味着什么；引言连接问题、研究路径、结果和文献贡献；数据部分说明来源、样本构建和限制；理论部分把机制与命题的直觉讲清楚。

值得提取的是各部分的功能与信息依赖。具体段数、词数、roadmap 和“文献综述一定放哪里”应结合文体和目标期刊，不机械继承成全局规则。

### 3.3 按研究类型调整表达任务

主文件明确其默认偏向应用微观，并提供理论、混合、结构论文和宏观等分支。专项方法文件也提示 DiD、IV、RDD 等叙述重点不同。这种设计的价值在于：让写作检查关注研究内容，而非对所有论文使用同一套语言润色清单。

本轮没有逐条复核全部计量建议；这里确认的是分流设计及其文字内容，不表示其中所有方法建议已通过专业审核。

### 3.4 用审阅视角组织问题

方法、领域贡献、表达三个视角分别关注不同缺口；主 skill 要求每个问题说明哪里不对、为什么重要、怎样修改，并优先列出三项最有影响的修改。

可借鉴的是问题分解和反馈格式。三个模拟视角不等于三个独立专家，也不自动提供独立证据。

## 4. 规则如何从来源转成指令

[SOURCES_RANKED.md](../../repos/econ-writing-skill/sources/SOURCES_RANKED.md) 声称汇集 50+ 来源，按作者/机构、经济学相关性、完整程度等排序，并列出预期 PDF 文件名。
本地仓库没有附带这些 PDF；常规安装脚本只打包五个 skill 文件，来源目录、示例和 evals 不会随该安装路径一起进入 skill 包。
因此“来源清单存在”不同于“模型执行每条规则时自动检索并验证来源”。本轮只抽查下表涉及的来源，未确认全部来源都与所引建议一致。

| 规则主题 | 上游 skill 的处理 | 原始来源与核查判断 | 对使用的影响 |
|---|---|---|---|
| 引言结构 | 将结果段落单列，并合并文献回顾与贡献，标为 Head / Evans / Bellemare 综合公式 | Head 原文为 Hook、Question、Antecedents、Value-added、Roadmap，允许后两者交织；skill 是综合改编。[Head 原文](https://blogs.ubc.ca/khead/research/research-advice/formula) | 可以作为候选结构，不能把所有细节都归为 Head 的原始要求 |
| 引言中结果占比 | 多处把 25–30% 写成执行要求 | Evans 对实证发展经济学论文做结构观察，记录了这一常见比例，同时指出变化形式。[Evans 原文](https://www.cgdev.org/blog/how-write-introduction-your-development-economics-paper) | 保留“让读者充分理解结果”的功能；该比例不是跨文体有效性证明 |
| roadmap 和文献综述位置 | 常规论文分支要求引言以 roadmap 结束，文献综述不单列 | Cochrane 认为 roadmap 非必需，并允许将文献回顾单独设节或分隔。[Cochrane 原文，印刷页 2](https://www.fma.org/assets/docs/membercontent/writing_cochrane.pdf) | 来源内部并非完全一致；应记录作者选择及条件 |
| 结论中的局限 | 标注 Bellemare adapted，采用总结、含义、后续研究三部分；允许简短具体局限，但弱化泛化 caveats | Bellemare 原文列出四项，明确将 limitations 作为一项。[Bellemare 原文](https://marcfbellemare.com/wordpress/12060) | 不是“完全禁止局限”；但不能将弱化局限的改编当作原作者共识 |

这些差异不直接证明改编无效，而是说明综述需要保留“原始建议—改编内容—适用条件—待检验效果”的链条。标题中出现名家姓名，并不能代替这条链条。

另外，审阅清单 L116 将 P&P 描述成 AER 的短文途径；AEA 官方说明 P&P 自 2018 年起已是独立刊物。[AEA 官方页面](https://www.aeaweb.org/journals/pandp)
这是一项已核验的事实修正，其余投稿政策、格式限制与 AI 披露要求在实际投稿时仍需逐项查当时的官方说明。

## 5. 四种模式怎样选择

下面是基于固定快照内容的场景匹配建议，尚不是实测效果排名。

| 模式 | 已有什么输入时合适 | 它被要求产出什么 | 我们需要怎样验收 |
|---|---|---|---|
| Drafting，起草 | 已有问题、研究设计、主要结果、相关文献和证据位置 | 按章节组织草稿；未知项以 `[AUTHOR: ...]` 标注 | 所有事实可追溯；缺材料时没有补造结果；因果强度与研究相称 |
| Rewriting，改写 | 已有原文，需要改善结构、清晰度或简洁度 | 修改稿及简短修改说明 | 对照检查数字、对象、方向、限定、作者意图是否保持 |
| Reviewing，审阅 | 已有段落或草稿，希望先定位问题 | 问题、理由、修改建议；快扫或深入审阅 | 每项批评有原文位置；材料不足时标明未知 |
| Auditing，审计 | 有完整论文及主要支撑材料，需要整理修改优先级 | 三个视角、分项分数、前三项修改 | 将分数当内部反馈；不能外推到真实投稿成功率 |

README 区分四种模式，但主文件将 REVIEW/AUDIT 合并成一块，可能在用户只要诊断时也引入评分。使用时最好直接说明是否要改稿、是否评分，以及评审范围。

### 对我们当前工作的适用性

- 已有结果表和方法说明，准备写结果段：可选 Drafting，并要求每条量级解释指向相应表格。
- 已有引言，想知道问题、贡献和结果是否清楚：先选 Reviewing；确认诊断后，再决定 Rewriting 范围。
- 句子拖沓、空泛、重复：可选 Rewriting，并保留事实与限定清单。
- 正在做系统性文献检索或确定未知领域的研究缺口：此 skill 不能替代检索、阅读和证据比较；它适合在材料形成后帮助组织表达。
- 本项目的工具综述：可借鉴 `specialized-tasks.md` 的 SURVEY/REVIEW 分支，围绕研究问题和方法做综合；不能误用普通论文引言中“只讨论少数近邻、把综述放进引言”的分支。
- 投稿政策核验、研究设计有效性认证、真实审稿结论：不能由其静态清单或自评分直接确认。

## 6. 可靠性证据与明确边界

### 6.1 占位符规则与非学术分支存在重要差异

主 skill 的 DRAFT 分支（L625 起）要求作者补充缺失材料；Citation Integrity（L457 起）要求核验引用和所引结果。这些是有价值的文字约束，但没有绑定证据账本或程序检查。

`specialized-tasks.md` L47 则在政策短评/面向公众写作分支中，允许遇到未知数字时补充可辩护的示意数值，并在文末加说明。这可能让读者把示意数值误认成研究证据。
本项目不继承这一补值规则：未知事实应询问、明确留缺、或不作该项论断；若任务确实要求教学假设案例，必须在案例就地标明其假设性质。

### 6.2 示范文本不是经核验的真实修订对

[before-after.md](../../repos/econ-writing-skill/examples/before-after.md) 包含 12 组示范，并在末尾注明由 skill 生成。
第一组的输入没有国家、样本和系数，输出却增加了具体地点、数量与效果大小。文件没有展示这些信息的原始材料。
这能演示目标文风，却不足以证明系统从给定输入保真改写；也不能只凭示例就断言一次真实使用发生了幻觉。我们缺少其完整生成条件。

### 6.3 18 个 eval 是评价说明，不是已公布效果结果

[test-cases.md](../../repos/econ-writing-skill/evals/test-cases.md) 有 18 个 prompt、预期行为和失败模式，末尾要求逐条运行、人工检查、记录通过率。
本快照没有与之配套的自动写作评测 runner、逐样本输出、模型条件或结果报告。

Test 1 未给研究结果却要求具体效果量；Test 4 允许使用占位符；Test 18 仅给短引言却要求三视角及总分。它们可以启发测试设计，但输入充分性、缺失信息处理和评分范围还不一致。
未来试用应先补清事实包，并把“不编造”与表达改善分开验收。

### 6.4 工程测试和论文质量评价分开理解

[test_plugin_package.py](../../repos/econ-writing-skill/tests/test_plugin_package.py) 主要检查包 manifest、五文件镜像、安装路径、备份、幂等与失败保护。
本轮直接用 SHA-256 核验：五个 canonical 文件与 `.claude/skills/econ-write/`、`.agents/skills/econ-write/` 的对应文件均一致；HEAD 未改变，工作树干净。
这是分发一致性的证据，没有运行安装器或这些测试，也没有得到写作质量通过率。

审阅清单把 90–100 分映射为 top-5 投稿就绪。未见支撑该阈值的人类校准或投稿结果验证，且没有不可被其他分项补偿的事实有效性门槛。使用时优先保留分项理由和证据，不采纳该分档作为外部质量认证。

## 7. 我们可以怎样用：三个任务模板

以下是本项目拟采用的使用方式，保留上游有用原则，同时明确任务输入和事实边界；不是上游已有且已验证的协议。

### 先诊断引言

```text
按 econ-write 的 Reviewing 模式诊断以下引言。
输入：引言原文、问题与贡献说明、主要结果表、近邻文献笔记。
先概括每段功能，再检查问题、方法、结果和贡献是否清楚且有证据。
每项问题给原文位置、理由及修改方向，优先列出三项最重要的问题。
此次只做诊断，不改全文、不评分；缺材料时说明无法判断的内容。
```

### 保真改写一个段落

```text
按 econ-write 的 Rewriting 模式改写以下段落，改善清晰度和信息顺序。
数字、比较对象、估计对象、因果限定和引用保持不变；不补造事实。
输出修改稿，并逐项说明实质变化与保留的限定。
若更具体的表达需要我补充材料，用 [AUTHOR: 所需信息] 标出。
```

### 从已有证据起草结果段

```text
按 econ-write 的 Drafting 模式，依据提供的表格和方法说明起草结果段。
输入包括研究设计、变量单位、主估计、标准误/区间、基准均值与已知局限。
先写主要发现，再解释量级和适用范围；每项数值解释标明表格位置。
材料不足时列出缺项；不自行补充显著性、机制检验或稳健性结果。
```

## 8. 对后续项目比较的输入

本项目最值得继续学习三项机制：把写作建议转成章节动作；将低频任务分到专项文件；按问题、影响和修改办法形成审阅反馈。
需要在我们自己的设计中补充的是：输入材料要求、规则来源与改编关系、事实保持检查，以及规则冲突的处理顺序。

读 AER-Skills 时可围绕三个问题比较：它是否把这些文字要求变成明确的阶段产物；怎样检查证据与论断对应；缺材料或检查失败后如何返回相应任务。
下一次若先继续 econ-write，适合用一段真实引言做诊断，再围绕诊断结果进行有限改写，而不是立即用其自评分选择“最佳版本”。这些都是后续候选，尚未执行。
